1) Core Data Contract: ProductDNA (must implement exactly)

Implement these TS types on both server and mobile (zod validation required).

export type Currency = "USD" | "TRY";
export type Country = "USA" | "TURKEY";
export type Condition = "NEW" | "USED" | "LIKE_NEW";

export type ProductDNA = {
  title: string; // canonical: "Apple Watch Series 9 45mm GPS"
  category: "Electronics" | "Fashion" | "Watch" | "Other";
  brand?: string;
  model?: string;        // "Series 9", "Saffiano Leather Wallet"
  variant?: Record<string, string>; // size, color, material, gps/cellular, etc
  identifiers?: { gtin?: string; sku?: string; serial?: string };
  condition: Condition;
  country: Country;
  confidence: { visual: number; ocr: number; barcode: number; overall: number };
  mustHaveTokens: string[]; // strict tokens: "45mm", "Series 9", "GPS"
  negativeTokens: string[]; // "case", "band", "strap", "accessory", "cover"
  searchQueries: string[];  // 6-12 queries: TR + EN, strict -> loose
  imageHash?: string;       // for duplicate detection
};


Offer model:

export type Offer = {
  source: string;      // Target, BestBuy, Trendyol, Hepsiburada, Amazon...
  url: string;
  title: string;
  amount: number;
  currency: Currency;
  country: Country;
  condition: "NEW" | "USED";
  shipping?: number;   // same currency
  taxIncluded?: boolean;
  inStock?: boolean;
  fetchedAt: number;
  raw?: any;           // keep original for debugging
  matchScore?: number;
  matchReasons?: string[];
  isOutlier?: boolean;
  isDuplicate?: boolean;
  isVerified?: boolean; // only if matchScore >= threshold
};


Valuation:

export type Valuation = {
  displayCurrency: Currency;
  marketValue: number;   // median of verified, non-outlier
  min: number;
  max: number;
  median: number;
  offers: Offer[];       // cleaned + scored + normalized
  excluded: Offer[];     // outliers, low-match, accessories
  notes: string[];       // user-facing explanations
};

3) Identification engine (must be high accuracy)

Implement services/identify with multi-signal approach:

3.1 Image capture rules (mobile)

On Scan screen:

take 2–3 frames (burst) and pick sharpest using simple blur metric

crop center object lightly (do not cut edges)

compress to reasonable size for upload (keep detail)

3.2 Barcode first

If barcode/QR present, detect it first (Expo compatible lib).

If GTIN found, set confidence.barcode = 1.0 and include as identifier.

Generate searchQueries using GTIN + brand/model tokens.

3.3 OCR second

Run OCR to extract printed model tokens (Series, size, model codes).
Set confidence.ocr.

3.4 Visual model last (Gemini/VLM or current model)

Call my existing vision model and force structured JSON output for:

brand, model, variant, mustHaveTokens, negativeTokens, confidence.visual

Provide 8–12 searchQueries in TR+EN (strict -> loose)

Provide category guess

Compute overall as weighted:

if barcode present: overall 0.95–1.0

else overall = 0.55visual + 0.35ocr + 0.10*barcode

3.5 “Confirm & Refine” trigger

If overall < 0.80 OR missing key variant fields:
Return dna but also a flag needsRefine=true for mobile.

5) Matching engine (this is the key: must implement)

Create services/match/matchOffers.ts

5.1 Tokenization

Normalize strings:

lower-case

remove punctuation

normalize spaces

normalize units (mm, gb, inch)

map synonyms (cellular = lte)

5.2 Match scoring

For each offer:

Start score at 0

+30 if brand appears

+35 if model appears

(5 * number_of_mustHaveTokens_matched) up to +25

+10 if category keywords align

-40 if any negativeTokens present (case/strap/accessory/cover/band-only)

-30 if mismatched variant token detected (e.g. 41mm vs dna says 45mm)

-20 if title too generic (no mustHaveTokens) AND dna overall < 0.9
Clamp 0..100.

Set:

offer.matchScore = score

isVerified = score >= 75 (configurable)

Save matchReasons list (“matched: 45mm, series 9; excluded: band”)

5.3 Accessory trap rules (must)

Hard exclude if title contains:

“band”, “strap”, “case”, “cover”, “screen protector”, “charger”, “adapter”, “box only”
(in TR equivalents too: kordon, kayış, kılıf, ekran koruyucu, şarj)

Put these into excluded.

6) Cleaning: duplicates + outliers + currency normalization

Create services/normalize and services/valuate.

6.1 Duplicate merge

Duplicate if:

same finalUrl

OR same source + same normalizedTitle + same amount±1%
Mark duplicates, keep best-quality one.

6.2 Outlier detection

Use robust method:

take verified offers only

compute median + IQR

outlier if outside [Q1-1.5IQR, Q3+1.5IQR]
Mark isOutlier=true and move to excluded (but still show collapsed in UI).

6.3 Currency & country correctness

Never show TR offers as USD accidentally.

Valuation is computed in displayCurrency.

6.4 Valuation rule

Market value = median of verified + non-outlier offers in same condition bucket.
If not enough verified offers (<3):

expand threshold down to 70 OR request refine step on mobile.
Return user-facing notes.
